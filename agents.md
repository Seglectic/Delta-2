## Keybindings

### Delta Modifier

Caps Lock activates the delta layer. Two backends are supported — set `backend` in `delta.conf`:

**keyd** (default, QMK keyboard):
- QMK firmware maps Caps Lock → `KEY_F20`
- `keyd` intercepts `KEY_F20` at evdev level (before XKB) and re-emits `Ctrl+Alt+Meta+Key`
- Config: `/etc/keyd/default.conf` (generated by `delta apply`)
- Requires keyd installed system-wide; `delta setup` grants group access

**xremap** (standard keyboard, work machines, Steam Deck):
- Runs as a user systemd service — no root required, per-user, survives OS updates
- Remaps Caps Lock (held) → virtual `KEY_F20`, then maps `KEY_F20+key` → `Ctrl+Alt+Meta+Key`
- Config: `~/.config/xremap/config.yml` (generated by `delta apply-user`)
- Set `modifier_key = capslock` and `backend = xremap` in `delta.conf`
- Install: `delta install-xremap` for platform-appropriate instructions

**macOS**: Karabiner maps F20 → `Ctrl+Alt+Meta`

**Critical XKB gotcha (keyd path only)**: XKB maps `KEY_F20` → `XF86AudioMicMute`. KDE shows
F20 as "Microphone Mute" in its UI. keyd bypasses this entirely. Do not try to unbind the
KDE mic mute action — just ensure keyd is running.

### Window Management (KDE/KWin)

Display: ultrawide 21:9 aspect ratio. Layout philosophy: 2/3 + 1/3 splits.
Right hand stays on mouse — all bindings are left-hand operable.

| Shortcut   | Action                                                        |
|------------|---------------------------------------------------------------|
| Delta+W    | Fullscreen (full screen width × height)                       |
| Delta+A    | Tile to left 2/3 in a 2/3 + 1/3 KWin layout                  |
| Delta+D    | Tile to right 2/3 in a 1/3 + 2/3 KWin layout                 |
| Delta+Q    | Tile to left 1/3 in a 1/3 + 2/3 KWin layout                  |
| Delta+E    | Tile to right 1/3 in a 2/3 + 1/3 KWin layout                 |
| Delta+Left | Tile to left 1/2 in a 50/50 KWin layout                      |
| Delta+Right| Tile to right 1/2 in a 50/50 KWin layout                     |
| Delta+R / F19 | Focus or launch Discord, then tile it to the left 1/3     |
| Delta+V    | Focus or launch Obsidian                                     |
| Delta+C    | Focus or launch VS Code                                      |
| Delta+X    | Focus or launch Konsole                                      |
| Delta+S    | Float at fixed 1024×768, centered on screen                   |
| F17        | Alt+Up — move up Discord DM list (Discord focused only)       |
| F16        | Alt+Down — move down Discord DM list (Discord focused only)   |

These mirror the Windows/macOS Delta-2 workflow (github.com/Seglectic/Delta-2).
KDE's built-in QuickTile can't do 2/3 or 1/3 widths — custom KWin tiling script required.

### v2 Working Notes

- `Delta+Q/A/D/E/Left/Right` now use KWin's root tile tree plus a geometry fallback.
- The working horizontal split enum in this scripting environment is numeric `1`.
- Final placement is mapped through `workspace.clientArea(KWin.MaximizeArea, window)` rather than
  full output geometry so panels/taskbars are respected.
- A small inset is applied to better match KDE's drag-to-tile feel:
  `left=2`, `top=4`, `right=4`, `bottom=4`
- Delta actions are ignored for fullscreen windows by default. This is the main safeguard against
  fat-fingering a game window.
- Optional deny lists exist for non-fullscreen edge cases:
  `[guards].ignored_desktop_files` and `[guards].ignored_classes`
- Repeated placement into the same tile does **not** automatically push the existing window into
  the opposite tile. Current behavior leaves the existing window in place so windows can stack in
  the same zone if desired.
- `Delta+W` and `Delta+S` remain plain geometry actions, not tile-tree actions.
- `Delta+R/V/C/X` are app actions. Existing windows are focused in KWin; launch fallback is handled
  through a user systemd unit (`delta-launch@.service`) that runs the local
  `~/.local/bin/delta/delta-launcher` helper.
- Discord is special-cased: after focus or launch, it is also tiled into the left `1/3`.
- If an app hotkey targets a window that is already active, the window is minimized. Pressing the
  hotkey again restores the minimized window and focuses it.
- Obsidian is bound under a fresh KDE shortcut ID (`DeltaObsidianV`) on `Delta+V` because the old
  `Delta+Z` path got stuck in stale KDE shortcut state.

### Tool Notes

- **ydotool**: input simulation only — cannot move or resize windows
- **xdotool**: does NOT work on Wayland — never use for the Wayland path
- KWin DBus (`qdbus6`) is the correct approach on Wayland for window geometry
- All user machines (home desktop, Steam Deck target) run Wayland

## Delta System — Architecture

### Stack

keyd backend (QMK keyboard):
```
Physical Caps Lock
  → QMK firmware outputs KEY_F20
  → keyd intercepts KEY_F20 at evdev (before XKB)
  → keyd: f20 = layer(delta); layer keys → C-A-M-<key>
  → KWin global shortcut: Ctrl+Alt+Meta+Key
  → registerShortcut() handler in KWin script
  → window tiled via w.frameGeometry or a KWin root tile
```

xremap backend (standard keyboard, work/immutable machines):
```
Physical Caps Lock
  → xremap user service intercepts at evdev (before XKB)
  → modmap: CapsLock held → KEY_F20; keymap: KEY_F20+key → Ctrl+Alt+Meta+Key
  → KWin global shortcut: Ctrl+Alt+Meta+Key  (same as keyd path)
  → registerShortcut() handler in KWin script
  → window tiled via w.frameGeometry or a KWin root tile
```

### File Layout

| Path | Role |
|------|------|
| `~/.local/bin/delta/delta` | Configurator CLI (`apply`, `apply-user`, `reload`, `status`, …) |
| `~/.local/bin/delta/delta.conf` | **Source of truth** — edit this, run `delta apply` |
| `~/.local/bin/delta/agents.md` | This file |
| `/etc/keyd/default.conf` | Generated by `delta apply` (keyd backend only) |
| `~/.local/bin/delta/delta-launcher` | Generated launcher script (replaces delta-app-launch) |
| `~/.config/xremap/config.yml` | Generated by `delta apply-user` (xremap backend only) |
| `~/.config/xremap/app-bindings.yml` | Generated by `delta apply` when `[app_bindings]` present (keyd backend) |
| `~/.config/systemd/user/xremap.service` | Installed by `delta apply-user` (xremap backend only) |
| `~/.config/systemd/user/xremap-appbindings.service` | Installed by `delta apply` when `[app_bindings]` present (keyd backend) |
| `~/.local/share/kwin/scripts/delta-tile/contents/code/main.js` | Generated KWin script |
| `~/.local/share/kwin/scripts/delta-tile/metadata.json` | KWin package metadata |
| `~/.config/autostart/delta-kwin.desktop` | Auto-loads KWin script on login |

### Configurator CLI

```bash
# keyd backend (default, QMK keyboard)
delta setup          # (once, sudo) — adds user to keyd group, makes /etc/keyd writable
delta apply          # regenerate keyd config + KWin script, reload both
delta reload         # reload keyd + KWin script without regenerating

# xremap backend (standard keyboard, work machine, Steam Deck)
delta install-xremap # print platform-appropriate install instructions for xremap binary
delta apply-user     # regenerate xremap config + KWin script, restart xremap service
delta reload-user    # restart xremap service only (no regeneration)

# shared
delta status         # show backend, keyd/xremap service state, KWin script state
delta render-launcher  # regenerate the user systemd launcher unit
```

After `delta setup` (keyd path), log out and back in once. After that, `delta apply` runs without sudo.

For the xremap path (including `[app_bindings]` on the keyd backend), the user must be in the
`input` group. `delta apply` detects this automatically and runs `sudo usermod -aG input $USER`
if needed — but a log-out/in is required before xremap can open input devices.

### delta.conf Format

```ini
[device]
keyboard_id = 3434:0151   # vendor:product (sudo keyd list-devices); use * for any keyboard
modifier_key = f20        # f20 (QMK default) | capslock (standard keyboard)
# backend = xremap        # keyd (default) | xremap — uncomment for non-QMK machines

[bindings]
# ID = KEY  x_start  width        (fractions of screen width)
# ID = KEY  fixed    width height  (fixed pixel size, centered)
# ID = KEY  tile     layout side   (associate window with a KWin tile)
DeltaTileLeft    = A      tile  thirds_right  left
DeltaTileRight   = D      tile  thirds_left   right
DeltaTileLeft3   = Q      tile  thirds_left   left
DeltaTileRight3  = E      tile  thirds_right  right
DeltaHalfLeft    = Left   tile  halves  left
DeltaHalfRight   = Right  tile  halves  right
DeltaDiscord     = R      app   discord
DeltaObsidianV   = V      app   obsidian
DeltaCode        = C      app   code
DeltaKonsole     = X      app   konsole
DeltaFullscreen  = W  0      1
DeltaCenterFixed = S  fixed  1024 768

[app_bindings]
# App-specific key remaps. When the named app is focused, the key emits the target chord.
# Format: app_class.KEY = Modifier+Key
# keyd backend: starts a supplemental xremap-appbindings service (requires input group).
# xremap backend: merged into main xremap config.
discord.F17 = Alt+Up
discord.F16 = Alt+Down

[aliases]
# Extra shortcuts that fire the same action as an existing binding.
# Format: binding_id = KEY  (bare key, e.g. F19, grave)
DeltaDiscord = F19

[guards]
ignore_fullscreen = true
# ignored_desktop_files = steam_app_2357570, lutris
# ignored_classes = wine, steam_app_2357570

[overrides]
# Per-app tile overrides. Format: app_class.KEY = x_start width
# Find window class: qdbus6 org.kde.KWin /KWin org.kde.KWin.queryWindowInfo
# org.kde.konsole.A = 0 1
```

### Tile Script Behavior

- Layouts currently supported by the generated KWin script:
  - `halves`: `1/2 | 1/2`
  - `thirds_left`: `1/3 | 2/3`
  - `thirds_right`: `2/3 | 1/3`
- The script first associates the window with a KWin tile, then explicitly writes `frameGeometry`
  using the tile's relative geometry projected onto `KWin.MaximizeArea`.
- This explicit geometry write is currently what makes the visual placement reliable.
- The KWin API accepts tile association before it visibly reflows the window, so the fallback
  geometry write is part of the working design, not just debug scaffolding.

### Critical: KDE Shortcut ID Stability

The `ID` field in `[bindings]` (e.g., `DeltaTileLeft`) is used directly as the
`registerShortcut()` ID in the KWin script. **This ID must never change.**

KDE persists shortcut key assignments in `~/.config/kglobalshortcutsrc` keyed by ID.
If you rename an ID:
- KDE creates a new empty entry for the new ID (no key assigned)
- The old ID's key assignment persists and conflicts
- Result: the shortcut silently does nothing

If you ever need to rename an ID, manually edit kglobalshortcutsrc to remove the stale entry.

### KWin Script Loading

The script is loaded via autostart `.desktop` file (sleep 2 then DBus load) rather than
the kpackagetool6 install path, which was unreliable. The autostart entry:

```
~/.config/autostart/delta-kwin.desktop
```

To manually reload without rebooting:
```bash
delta reload
```

## Proposed: deltad — Window Follow-Mouse (NOT IMPLEMENTED)

**Goal**: Delta+Tab held → active window follows mouse movement; release → window stays.

**Why KWin scripting alone can't do this**: KWin scripts can't listen to raw keydown/keyup
events with hold semantics — `registerShortcut` fires once on keydown, no keyup callback.

**Proposed approach** (hacky — user is researching alternatives before committing):

1. `deltad` — Python evdev daemon (systemd user service)
   - Watches keyd's virtual device (`/dev/input/by-id/keyd-virtual-keyboard`)
   - On `Ctrl+Alt+Meta+Tab` keydown: signals KWin script to start move loop
   - On `Ctrl+Alt+Meta+Tab` keyup: signals KWin script to stop move loop
   - Signal mechanism: write to a temp file that the KWin script polls via `setInterval`

2. KWin script side:
   - `setInterval` polling loop (e.g., every 50ms)
   - Reads signal file; when active, reads cursor position via `workspace.cursorPos`
   - Sets `w.frameGeometry` to follow cursor with some offset

**Problems with this approach**:
- `setInterval` polling is janky; 50ms = perceptible lag
- KWin scripting API may not expose cursor position (unconfirmed)
- Writing/reading temp files across process boundary is fragile
- The KWin script has no reliable keyup hook

**Alternatives to research**:
- KWin effect (C++ plugin) — can hook `grabbedKeyboardEvent` with full up/down semantics
- libinput-based daemon with Wayland protocol for window positioning (wlroots ext? KWin IPC?)
- KWin's built-in interactive move mode (`w.startInteractiveMoveResize()` or similar API)

## Multi-System Notes

| Machine | Backend | modifier_key | Notes |
|---|---|---|---|
| Home desktop | keyd | f20 | Keychron Q5 (3434:0151), QMK firmware |
| Work computer | xremap | capslock | Multi-user — keyd would affect all accounts |
| Steam Deck | xremap | capslock | Immutable SteamOS — /etc is read-only |

- All machines use Wayland/KDE Plasma; X11 compatibility is not a priority
- The KWin script is identical across all machines — same Ctrl+Alt+Meta+Key shortcuts
- xremap binary on immutable systems: install to `~/.local/bin/` (persists across OS updates)
- Steam Deck: install xremap binary via pre-built release zip; `cargo` not available by default
- On Steam Deck, `~/.local/` and `~/.config/` survive SteamOS updates; `/etc/` does not

## Debugging

```bash
# keyd backend
sudo keyd monitor          # raw evdev events as keyd sees/transforms them
journalctl -u keyd -f      # live keyd service log
sudo keyd list-devices     # verify keyboard_id is being picked up

# xremap backend
systemctl --user status xremap        # service health
journalctl --user -u xremap -f        # live xremap log
cat ~/.config/xremap/config.yml       # inspect generated config

# app_bindings (keyd backend + supplemental xremap)
systemctl --user status xremap-appbindings
journalctl --user -u xremap-appbindings -f
cat ~/.config/xremap/app-bindings.yml

# shared
delta status               # check backend + service state + KWin script
qdbus6 org.kde.KWin /KWin org.kde.KWin.queryWindowInfo   # get active window's WM_CLASS
journalctl --user -b --no-pager | rg "DELTA:"            # KWin script debug output
```

Hold Delta+A — KWin should tile the active window. If nothing happens:
- keyd path: check `keyd monitor` for `Ctrl+Alt+Meta+a` emission
- xremap path: check `journalctl --user -u xremap -f` for the key event being caught
