## Keybindings

### Delta Modifier

Caps Lock base remap is **F20**. Handled at **QMK keyboard firmware** level — do not touch at OS level.

- **macOS**: Karabiner maps F20 → `Ctrl+Alt+Meta`
- **Linux/KDE**: `keyd` intercepts `KEY_F20` at evdev level (before XKB, before Wayland compositor)
  and re-emits `Ctrl+Alt+Meta+Key` when the delta layer is active.
  Config: `/etc/keyd/default.conf` (generated by `delta apply`).

**Critical XKB gotcha**: XKB maps `KEY_F20` → `XF86AudioMicMute`. KDE shows F20 as
"Microphone Mute" in its UI. keyd bypasses this entirely by intercepting at evdev level.
Do not try to unbind KDE's mic mute action — just ensure keyd is running.

### Window Management (KDE/KWin)

Display: ultrawide 21:9 aspect ratio. Layout philosophy: 2/3 + 1/3 splits.
Right hand stays on mouse — all bindings are left-hand operable.

| Shortcut   | Action                                                        |
|------------|---------------------------------------------------------------|
| Delta+W    | Fullscreen (full screen width × height)                       |
| Delta+A    | Tile to left 2/3 in a 2/3 + 1/3 KWin layout                  |
| Delta+D    | Tile to right 2/3 in a 1/3 + 2/3 KWin layout                 |
| Delta+Q    | Tile to left 1/3 in a 1/3 + 2/3 KWin layout                  |
| Delta+E    | Tile to right 1/3 in a 2/3 + 1/3 KWin layout                 |
| Delta+Left | Tile to left 1/2 in a 50/50 KWin layout                      |
| Delta+Right| Tile to right 1/2 in a 50/50 KWin layout                     |
| Delta+S    | Float at fixed 1024×768, centered on screen                   |

These mirror the Windows/macOS Delta-2 workflow (github.com/Seglectic/Delta-2).
KDE's built-in QuickTile can't do 2/3 or 1/3 widths — custom KWin tiling script required.

### v2 Working Notes

- `Delta+Q/A/D/E/Left/Right` now use KWin's root tile tree plus a geometry fallback.
- The working horizontal split enum in this scripting environment is numeric `1`.
- Final placement is mapped through `workspace.clientArea(KWin.MaximizeArea, window)` rather than
  full output geometry so panels/taskbars are respected.
- A small inset is applied to better match KDE's drag-to-tile feel:
  `left=2`, `top=4`, `right=4`, `bottom=4`
- Repeated placement into the same tile does **not** automatically push the existing window into
  the opposite tile. Current behavior leaves the existing window in place so windows can stack in
  the same zone if desired.
- `Delta+W` and `Delta+S` remain plain geometry actions, not tile-tree actions.

### Tool Notes

- **ydotool**: input simulation only — cannot move or resize windows
- **xdotool**: does NOT work on Wayland — never use for the Wayland path
- KWin DBus (`qdbus6`) is the correct approach on Wayland for window geometry
- All user machines (home desktop, Steam Deck target) run Wayland

## Delta System — Architecture

### Stack

```
Physical Caps Lock
  → QMK firmware outputs KEY_F20
  → keyd intercepts KEY_F20 at evdev (before XKB)
  → keyd: f20 = layer(delta); layer keys → C-A-M-<key>
  → KWin global shortcut: Ctrl+Alt+Meta+Key
  → registerShortcut() handler in KWin script
  → window tiled via w.frameGeometry or a KWin root tile
```

### File Layout

| Path | Role |
|------|------|
| `~/.local/bin/delta/delta` | Configurator CLI (`apply`, `reload`, `status`, `setup`) |
| `~/.local/bin/delta/delta.conf` | **Source of truth** — edit this, run `delta apply` |
| `~/.local/bin/delta/agents.md` | This file |
| `/etc/keyd/default.conf` | Generated by `delta apply` |
| `~/.local/share/kwin/scripts/delta-tile/contents/code/main.js` | Generated KWin script |
| `~/.local/share/kwin/scripts/delta-tile/metadata.json` | KWin package metadata |
| `~/.config/autostart/delta-kwin.desktop` | Auto-loads KWin script on login |

### Configurator CLI

```bash
delta setup   # (once, sudo) — adds user to keyd group, makes /etc/keyd writable by group
delta apply   # regenerate keyd config + KWin script from delta.conf, reload both
delta reload  # reload keyd + KWin script without regenerating
delta status  # show current state of all components
```

After `delta setup`, log out and back in once. After that, `delta apply` works without sudo.

### delta.conf Format

```ini
[device]
keyboard_id = 3434:0151   # vendor:product (sudo keyd list-devices to find yours)

[bindings]
# ID = KEY  x_start  width        (fractions of screen width)
# ID = KEY  fixed    width height  (fixed pixel size, centered)
# ID = KEY  tile     layout side   (associate window with a KWin tile)
DeltaTileLeft    = A      tile  thirds_right  left
DeltaTileRight   = D      tile  thirds_left   right
DeltaTileLeft3   = Q      tile  thirds_left   left
DeltaTileRight3  = E      tile  thirds_right  right
DeltaHalfLeft    = Left   tile  halves  left
DeltaHalfRight   = Right  tile  halves  right
DeltaFullscreen  = W  0      1
DeltaCenterFixed = S  fixed  1024 768

[overrides]
# Per-app tile overrides. Format: app_class.KEY = x_start width
# Find window class: qdbus6 org.kde.KWin /KWin org.kde.KWin.queryWindowInfo
# org.kde.konsole.A = 0 1
```

### Tile Script Behavior

- Layouts currently supported by the generated KWin script:
  - `halves`: `1/2 | 1/2`
  - `thirds_left`: `1/3 | 2/3`
  - `thirds_right`: `2/3 | 1/3`
- The script first associates the window with a KWin tile, then explicitly writes `frameGeometry`
  using the tile's relative geometry projected onto `KWin.MaximizeArea`.
- This explicit geometry write is currently what makes the visual placement reliable.
- The KWin API accepts tile association before it visibly reflows the window, so the fallback
  geometry write is part of the working design, not just debug scaffolding.

### Critical: KDE Shortcut ID Stability

The `ID` field in `[bindings]` (e.g., `DeltaTileLeft`) is used directly as the
`registerShortcut()` ID in the KWin script. **This ID must never change.**

KDE persists shortcut key assignments in `~/.config/kglobalshortcutsrc` keyed by ID.
If you rename an ID:
- KDE creates a new empty entry for the new ID (no key assigned)
- The old ID's key assignment persists and conflicts
- Result: the shortcut silently does nothing

If you ever need to rename an ID, manually edit kglobalshortcutsrc to remove the stale entry.

### KWin Script Loading

The script is loaded via autostart `.desktop` file (sleep 2 then DBus load) rather than
the kpackagetool6 install path, which was unreliable. The autostart entry:

```
~/.config/autostart/delta-kwin.desktop
```

To manually reload without rebooting:
```bash
delta reload
```

## Proposed: deltad — Window Follow-Mouse (NOT IMPLEMENTED)

**Goal**: Delta+Tab held → active window follows mouse movement; release → window stays.

**Why KWin scripting alone can't do this**: KWin scripts can't listen to raw keydown/keyup
events with hold semantics — `registerShortcut` fires once on keydown, no keyup callback.

**Proposed approach** (hacky — user is researching alternatives before committing):

1. `deltad` — Python evdev daemon (systemd user service)
   - Watches keyd's virtual device (`/dev/input/by-id/keyd-virtual-keyboard`)
   - On `Ctrl+Alt+Meta+Tab` keydown: signals KWin script to start move loop
   - On `Ctrl+Alt+Meta+Tab` keyup: signals KWin script to stop move loop
   - Signal mechanism: write to a temp file that the KWin script polls via `setInterval`

2. KWin script side:
   - `setInterval` polling loop (e.g., every 50ms)
   - Reads signal file; when active, reads cursor position via `workspace.cursorPos`
   - Sets `w.frameGeometry` to follow cursor with some offset

**Problems with this approach**:
- `setInterval` polling is janky; 50ms = perceptible lag
- KWin scripting API may not expose cursor position (unconfirmed)
- Writing/reading temp files across process boundary is fragile
- The KWin script has no reliable keyup hook

**Alternatives to research**:
- KWin effect (C++ plugin) — can hook `grabbedKeyboardEvent` with full up/down semantics
- libinput-based daemon with Wayland protocol for window positioning (wlroots ext? KWin IPC?)
- KWin's built-in interactive move mode (`w.startInteractiveMoveResize()` or similar API)

## Debugging

```bash
sudo keyd monitor          # raw evdev events as keyd sees/transforms them
journalctl -u keyd -f      # live keyd service log
delta status               # check keyd + KWin script state
qdbus6 org.kde.KWin /KWin org.kde.KWin.queryWindowInfo   # get active window's WM_CLASS
journalctl --user -b --no-pager | rg "DELTA:"            # KWin script debug output
```

Hold Delta+A and check `keyd monitor` — should show `Ctrl+Alt+Meta+a` emission.
If nothing appears, run `sudo keyd list-devices` to verify `3434:0151` is being picked up.
